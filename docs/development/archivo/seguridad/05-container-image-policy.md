> **Applies to:** All Zenith container images shipped to production.

## 1. Build chain

| Stage               | Tool                | What is signed / attested                  |
| ------------------- | ------------------- | ------------------------------------------ |
| Source code         | git + signed commits | author + committer identity, GPG signed     |
| CI build            | GitHub Actions / GitLab CI | SLSA L3 provenance (in-toto)         |
| Image build         | BuildKit + cosign   | image signature (keyless, Fulcio + Rekor)   |
| Vulnerability scan  | Trivy + Grype       | SBOM (SPDX 2.3) + CVE report                 |
| Image registry      | GHCR / ECR          | signature + SBOM stored alongside image    |
| Deployment          | ArgoCD + Kyverno    | signature + SBOM verified on pull           |
| Runtime             | Falco + eBPF        | syscall + network monitoring                |

## 2. Base image

We use **distroless** (Google's `gcr.io/distroless/*`) for the production image:

- No shell, no package manager, no setuid binaries.
- Only the application + its runtime dependencies.
- Reduces attack surface by 95 %+ vs `debian:slim`.

**Production image:**

```dockerfile
FROM gcr.io/distroless/cc-debian12:nonroot AS runtime
COPY --from=build /app/zenith /usr/local/bin/zenith
COPY --from=build /app/dist /app/dist
USER 65532:65532
EXPOSE 8080 50051 9090
ENTRYPOINT ["/usr/local/bin/zenith"]
```

## 3. SBOM (Software Bill of Materials)

Every release image includes an **SPDX 2.3 SBOM** generated by `syft`:

```bash
syft packages docker.io/zuccadev-labs/zenith-backend:v1.0.0 \
  --output spdx-json \
  --output-file /tmp/sbom.spdx.json
```

The SBOM is:

- Attached to the image as an OCI artifact.
- Published to the GitHub release.
- Continuously monitored by **Dependency-Track** for new CVEs.
- Available to customers under NDA for compliance audits.

## 4. Vulnerability scanning

### 4.1 Build-time (CI)

- **Trivy** blocks any image with a `CRITICAL` CVE.
- **Grype** cross-checks against the Anchore feed.
- **OSV-Scanner** covers language-specific vulnerabilities.

### 4.2 Registry-time (continuous)

- Trivy + Grype re-scan on every image push.
- ECR / GHCR native scanning (Amazon Inspector / GitHub Advanced Security).
- Slack alert on any new CRITICAL or HIGH CVE.

### 4.3 Runtime (defence in depth)

- **Falco** detects anomalous syscalls (e.g. `execve` of unexpected binaries).
- **eBPF** monitors network egress and DNS.
- **Kyverno** blocks pods that mount sensitive paths or run as root.

## 5. Image signing (cosign + Sigstore)

```bash
# Sign with keyless OIDC (Fulcio) + Rekor transparency log
cosign sign --yes \
  ghcr.io/zuccadev-labs/zenith-backend@sha256:abc123...
```

- **Public key:** `https://zenith.io/cosign.pub`
- **Transparency log:** Rekor (`https://rekor.sigstore.dev`)
- **Verification:** done by ArgoCD + Kyverno on every pull.

## 6. SLSA Level 3

We target **SLSA L3** for all production images:

- [x] Source — signed commits, two-person review on main.
- [x] Build — hosted runner, hermetic, isolated.
- [x] Provenance — non-forgeable, in-toto v0.1.
- [x] Common requirements — identifier (SHA256) + signed metadata.

Verified via `slsa-verifier` in CI:

```bash
slsa-verifier verify-image \
  --image-uri ghcr.io/zuccadev-labs/zenith-backend:v1.0.0 \
  --source-uri github.com/zuccadev-labs/Zenith \
  --provenance-path /tmp/provenance.json
```

## 7. CVE response SLA

| Severity   | Patch SLA | Auto-rollout       |
| ---------- | --------- | ------------------ |
| CRITICAL   | 24 h      | yes (no canary)    |
| HIGH       | 7 d       | yes (canary 10 %)  |
| MEDIUM     | 30 d      | no (manual review) |
| LOW        | 90 d      | no (manual review) |

## 8. Image lifecycle

| Stage                | Retention                          |
| -------------------- | ---------------------------------- |
| Latest (mutable)     | always 1 (overwritten on push)     |
| Tagged (immutable)   | 1 year, replicated to backup region |
| EOL                  | kept for 90 d post-EOL for rollback |
